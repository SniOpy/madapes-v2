La méthode Madapes

Vous savez où nous en sommes.
Et ce que nous validons ensuite.

Chaque étape produit quelque chose de concret : un périmètre, une maquette, une fonctionnalité à tester ou une version prête à être publiée.

  1. 01
    Cadrage

    Nous clarifions votre projet.

    Nous échangeons sur votre activité, vos utilisateurs et vos objectifs. Je distingue les besoins essentiels des évolutions possibles pour définir une première version cohérente.

    Ce que vous recevez

    Un périmètre de travail, des priorités et un planning prévisionnel.

    À valider : les objectifs et le périmètre.
  2. 02
    Maquette Figma

    Vous voyez avant de développer.

    Je conçois les écrans et les parcours dans Figma. Vous découvrez l’organisation du contenu, la direction visuelle et les interactions prévues. Nous ajustons la maquette avec vos retours.

    Ce que vous recevez

    Un lien vers la maquette et, selon le projet, un prototype navigable.

    À valider : le design et les parcours clés.
  3. 03
    Organisation agile

    Nous avançons par sprints.

    Le développement est découpé en cycles de travail courts, appelés sprints. Pour chaque cycle, nous définissons les fonctionnalités prioritaires et les critères qui permettront de les valider.

    Ce que vous recevez

    Un plan de sprint avec les tâches prévues et un point de démonstration.

    À valider : les priorités du prochain sprint.
  4. 04
    Codage & preview

    Votre interface devient utilisable.

    Je développe les écrans et les fonctionnalités, principalement avec React et TypeScript. Une version de preview vous permet de tester les éléments livrés. Les modifications du code sont enregistrées dans un historique de versions.

    Ce que vous recevez

    Un lien de preview actualisé aux jalons convenus et une démonstration des fonctionnalités du sprint.

    À valider : les éléments livrés et les retours.
  5. 05
    Tests & recette client

    Nous vérifions ensemble.

    Nous contrôlons les parcours principaux, les formulaires et l’affichage sur mobile et ordinateur. Vous testez la version de preview ; les corrections sont suivies avant la validation finale.

    Ce que vous recevez

    Une version à valider, une liste de vérifications et le suivi des corrections.

    À valider : votre accord pour la mise en ligne.
  6. 06
    Mise en production

    Votre projet rencontre ses utilisateurs.

    Après votre validation, je publie la version approuvée sur l’environnement de production. Je vérifie les fonctions clés en ligne et vous transmets les éléments de prise en main prévus dans notre accompagnement.

    Ce que vous recevez

    Le lien de production, les accès convenus et les informations utiles pour la suite.

    Ensuite : maintenance et évolutions selon le projet.

La méthode est la même, le périmètre change selon votre projet. On le fixe ensemble au premier échange.

Le versioning : un historique clair des changements.

Le code est suivi avec Git : les modifications et les étapes de développement sont conservées. Cela permet de retrouver une évolution, comparer les versions et préparer les corrections. Les versions mises en production sont identifiées ; les modalités de retour à une version précédente dépendent de l’hébergement et des données du projet.

Avant de commencer

Vos questions.
Des réponses claires.

Je n’ai qu’une idée : peut-on démarrer ?

Oui. Nous commençons par clarifier le besoin, les utilisateurs et les actions essentielles. Ce cadrage permet de définir une première version et les éléments nécessaires au démarrage.

Dois-je avoir une maquette Figma ?

Non. Je peux concevoir la maquette dans le cadre du projet ou travailler à partir d’une maquette existante. Le périmètre du design est défini dans la proposition.

Comment se passent mes validations ?

Les points de validation sont prévus dans le planning : périmètre, maquette, démonstrations de sprint et recette finale. Vos retours sont regroupés et suivis pour que chacun sache ce qui est validé ou reste à corriger.

Puis-je ajouter une fonctionnalité en cours de projet ?

Oui. Nous examinons son intérêt et son impact sur le périmètre, le planning et les conditions du projet. Une évolution peut être intégrée à un prochain sprint ou prévue après le lancement, avec votre accord.

La preview est-elle visible par tout le monde ?

Les modalités d’accès sont définies au cadrage. Si le projet nécessite une preview protégée, ce besoin est intégré au choix de l’hébergement et vérifié avant le partage du lien. Un simple lien de preview n’est pas, à lui seul, une protection d’accès.

Que se passe-t-il après la mise en ligne ?

Je vous transmets les éléments de prise en main et les accès prévus. La maintenance, les corrections après livraison et les futures évolutions sont encadrées par les conditions convenues pour votre projet.
